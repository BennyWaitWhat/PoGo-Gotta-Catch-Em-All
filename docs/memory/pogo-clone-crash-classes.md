Crash classes and silent-failure classes seen 2026-09-03..06 while testing the injected Pokemod clone (pogo_clone/, runner in Termux, gadget on 127.0.0.1:27047, single-client):

1. **Stale in-game screens outlive the script.** Every CustomMenu screen (an ARSettingsGuiController the clone creates) holds UnityEvents and a `Dismissed` System.Action whose `invoke_impl` is a Frida NativeCallback. Reloading the script frees those callbacks but leaves the screens; ANY managed call that raises them is a jump into freed memory. **Calling Dismiss() on a stale screen crashed the game (tombstone_27, 2026-09-06)** -- the earlier "dismiss stale screens at startup" rule was WRONG. Correct rule: at startup only inventory them and NULL the `Dismissed` field (GuiController offset 0x78, a plain field write executes no managed code); never Dismiss() or tap a stale screen. Pokemod never meets this because it restarts the game instead of hot-reloading (that is what its restartRequired flow is for).
2. **A managed NullReference inside a Create() becomes a process abort.** frida-il2cpp-bridge installs a fault handler; il2cpp's own null-read → NullReferenceException conversion is pre-empted and the game dies with "terminating due to uncaught exception of type Il2CppExceptionWrapper" (tombstones 25/28: UnityMain SIGSEGV, low fault addr). Validate before any Create()/factory call (prefab alive via `UnityEngine.Object.op_Implicit`), refuse nested `open()`, and log the caller stack on every `open()`.
3. **Silent mis-wiring traps (no crash, control just does nothing):** `Component.GetComponent` has two argc=1 overloads (Type/String) -- match by parameter type; `DiContainer.Resolve` has three argc=1 overloads -- match `System.Type`; `SceneContextRegistry.TryGetSceneContextForScene` must use the String overload (the by-value `Scene` struct cannot be marshalled); UGUI `Toggle` keeps its event in the PUBLIC field `onValueChanged` (Slider `m_OnValueChanged`, Button `m_OnClick`); Pokemod takes the Button/Toggle with GetComponent on the ROW ROOT -- a depth-first search picks a child and the write lands where no finger hits; `Method` objects taken off an `Il2Cpp.Class` are unbound (take them off the `Il2Cpp.Object`); `TextInputDialog/Data` is a reference type -- `new()` not `alloc()`.
4. **Pokemod's pump exists.** `Niantic.Zeppelin.Scheduler.Scheduler.LateUpdate` (Zeppelin.dll, argc=0) IS on this build; the clone's earlier "does not exist" claim came from a dump without nested types. The oracle dumper now recurses `il2cpp_class_get_nested_types` (71,651 classes vs 46,619) and spells nested types "Outer/Nested" exactly as Pokemod does.

**Why:** the user plays on this phone while I test; each crash costs them a game restart, and a control that silently does nothing looks "done" until someone taps it.

**How to apply:**
- Never attach the clone while Pokemod is injected. THE RELIABLE DETECTOR (2026-09-08, after I attached on top of Pokemod twice because a sorted+truncated thread grep hid it): `ss -xp | grep pokemod-injecto` -- Pokemod's injector processes (`pokemod-injecto`, spawned by com.pokemod.app.public) hold ESTABLISHED unix sockets into `clabs.pokemongo`; also `pgrep -f pokemod-injecto` and the `pool-floyd` + `gum-js-loop` + `gmain` + `gdbus` threads in the game. Pokemod does NOT use the gadget's TCP port 27047 (that listener is ZygiskFrida's injected frida-gadget -- our pogo_extract tooling, not part of the game APK; both clients can coexist, which is exactly the two-Fridas hazard in [[project-pogo-spoof-stack]]). To clear it, with the user's OK: `am force-stop com.pokemod.app.public`, kill the injectors, force-stop + relaunch PoGo, re-run the detector before attaching.
- Drive the agent from the desktop through `device/cmd.sh <fn> [arg]` (runner polls cmd.json; frida-python maps snake_case; "~" = space, "|" splits args) or write cmd.json via base64 for anything with spaces; never a second Frida attach. Screen is 960x2142 (×3.556 from a 270-px thumbnail).
- Prove a control two ways: `invokeControl` (event wired) AND a real tap (hit-testing).

**Two build/deploy gates learned 2026-09-09 (both cost a live cycle):**
1. **`node --check` on the compiled agent is NOT a gate.** A duplicate top-level identifier across two `agent/*.js` files (`fieldOf` in A_Obfuscation.js and A_PersistentPrefs.js) passed `node --check agent.build.js` -- which parses as a SCRIPT, where duplicate function declarations are legal -- then failed in-game with `Identifier 'fieldOf' has already been declared`, because frida-compile emits an ES MODULE where it is fatal. REAL GATE: strip frida-compile's `📦 / <bytes> / ✄` header and `node --check` the body as a `.mjs`. Cheap pre-check: scan `agent/*.js` for any top-level name declared in more than one file. (That `📦/✄` framing is also why `node --check agent.pogoclone.js` always "fails" -- frida parses it fine; do not chase it.)
2. **Never execute a script file in `/data/local/tmp`.** Files there left root-owned by earlier sessions cannot be overwritten by the adb shell user, the write fails, and `su -c 'sh /data/local/tmp/x.sh'` then runs the STALE script -- on 2026-09-09 that silently launched the clone with `--relaunch` and force-restarted the user's game. Deliver device scripts by piping base64 into `su` over stdin instead: `adb shell "echo <b64> | base64 -d | su -c sh"` -- no file, nothing stale.

**`il2cpp_gchandle_new` returns 0 on 0.427.0** -- pinning silently yields no handle, so any managed pointer "held" across hooks via `CUI.pin`/`CUI.deref` is actually null. Use a validated raw pointer as the fallback (`unityAlive()`-gated); the GC here is bdwgc and non-moving, so raw pointers are stable. See [[pokemod-vpgp-tweaks-module]].

**NEVER `pkill -9` a frida injector (2026-09-11).** `device/inject_one.py` and `device/launch_clone.py` both install SIGTERM handlers that run `script.unload()` + `session.detach()`, and the launcher's own injector-kill step already escalates properly (SIGTERM -> wait up to 10 s for /proc to vanish -> only then SIGKILL). A manual `pkill -9` bypasses all of it and can orphan Interceptor trampolines in the game with no JS runtime behind them; re-injecting into the same pid then stacks a second set on top. Correct stop: `pkill -f launch_clone.py; pkill -f inject_one.py`, wait for the pids to exit, escalate only if they survive. Suspected cost: tombstone_07 (2026-09-09 02:22, game pid 21852 -- the pid the clone had been attached to, UnityMain, null deref 0x470, frame #00 in anonymous executable memory, ~5 min after a `pkill -9`). Unprovable from the tombstone alone; treat as caused-by-us until shown otherwise. Note `gum-js-loop`/`frida-gadget` markers in a tombstone prove NOTHING on this phone -- ZygiskFrida's gadget is in every PoGo launch.

**Controller base classes live in namespace `Niantic.Holoholo.NUI`, not `.UI` (2026-09-11).** `GlobalErrorController` (UI) -> `NUI.LegacyGuiController` -> `NUI.GuiController`, and `Dismiss argc=0` plus the `Dismissed` field @0x78 are on `NUI.GuiController`. An oracle `has`/`show` against `Niantic.Holoholo.UI.GuiController` returns NOT FOUND and will make you "find" a defect that does not exist -- always let the parent walk resolve, and query the NUI name. Same shape for nested factories: `GlobalErrorController/Factory` declares only `.ctor`; `Create argc=1` comes from `Niantic.Holoholo.Util.ConfiguredPrefabFactory` generic-arity-3 (the arity-2 variant's Create is argc=0, so the generic arity is load-bearing).

**An overriding `status()` can hide a detector (2026-09-11).** `src/pogoclone.ts` overrides the core's `status()` and rebuilt `core` without the `pump` key, so `launch_clone.py` printed `pump=None` forever while the pump was installed and ticking. `PUMP` is a top-level `var` in an ES-module bundle and is NOT reachable from the TS realm -- only `CLONE`, `register`, `CORE_RPC` are pinned to globalThis -- so mirror such flags onto `CLONE` (`CLONE.pump`). Use `core.frame` advancing as the real proof the pump ticks (734 -> 971 in 8 s), which also proves `onTick` -> `CUI.Utils.drain()` -> the `runOnMain` queue drains.
