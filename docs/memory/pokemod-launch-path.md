Observed live on the Pixel 9 Pro with a root watcher (pogo_clone/device/watch_pokemod_launch.sh) while the user relaunched with Pokemod, 2026-09-08 00:59:

**Sequence (from Pokemod's own logcat tags PKMD / HALService / ServiceStateManager, pid = com.pokemod.app.public):**
1. `Attempting to kill game and injector blocking` -> `Step 1: Closing injector` -> `Step 2: Killing game and injector` -> `Cleanup successful. Starting injection...`
2. `[MAIN INJECTION] Script Start` -> `Starting activity...` (launches the game) -> `Waiting for process...` -> `Waiting for libNianticLabsPlugin.so...` -> `Library loaded` -> `Waiting delay 0us` -> `Executing injection...` (about 1 s after the activity start, BEFORE il2cpp is up: their agent has an "early" stage).
3. `[VPGP INJECTION]` targets `com.nianticlabs.pokemongo:pgp` (the game's Go Plus service process), waits for `libholoholo.so`, injects `agents/vpgp_agent` (39,800 B) -- their VIRTUAL GO PLUS.
4. State machine: `ServiceStateManager: PREPARING -> RUNNING (Cleanup complete, injection active)`.

**The injector command line (root, parent chain injector <- sh <- magiskd, i.e. `su -c`; -P as of Pokemod 13.3.3, 2026-09-20):**
```
/data/user/0/com.pokemod.app.public/files/injector/pokemod-injector -p <pid> -s /data/user/0/com.pokemod.app.public/files/agents/main_agent -R v8 -P {"uuid": "<16 hex>", "refreshToken": "<JWT>", "apiBaseUrl": "https://discovery.pokemod.dev/hal/", "recoveryMode": false, "injectionType": "attach", "targetLibrary": "libNianticLabsPlugin.so", "signals": {"sessionId": "<secret>", "grant": "<secret>", "source": "hal", "baseUrl": "https://signals.pokemod.dev", "attemptId": "<id>"}}
```
The vpgp_agent injector (into `:pgp`) carries the same -P. `refreshToken`, `signals.grant` and `signals.sessionId` are credentials: redact them in any quote.
`-p/-s/-R/-P` are frida-inject's flags: **pokemod-injector IS frida-inject renamed** (32.9 MB static build with V8; strings carry Gum, `floyd:rpc` transport, `re.floyd.AgentSession`, `.floyd 0x%zx`). It stays alive holding the session (threads `pokemod-injecto`, `pool-floyd`, two obfuscated) with Unix sockets into the game; the agent receives `init("early", params)` exactly like frida-inject's `--parameters`. `files/injector/pokemod-injector`'s mtime tracks the most recent game launch, but `files/agents/{main_agent,vpgp_agent}` kept the Pokemod app's own start time through two game relaunches (observed 2026-09-20): agent mtime is not the launch time. Their APK libs (libconceal.so, libfancier.so) are unrelated to injection.

**Detector for "Pokemod is in the game":** `ss -xp | grep pokemod-injecto` (ESTAB unix sockets into clabs.pokemongo), `pgrep -f pokemod-inject`, threads `pool-floyd` + `gum-js-loop` + `gmain` + `gdbus` in the game. A sorted, truncated thread grep hid this from me twice.

**NOT Pokemod:** `ZygiskFrida` (Magisk module lico-n, v1.9.0, installed 2026-05-09) injects `/data/local/tmp/re.zyg.fri/libgadget.so` into every PoGo launch after a 5000 ms delay and listens on 127.0.0.1:27047 -- that is the pogo_extract project's own tooling (see [[pogo-on-phone-catcher]], [[project-pogo-extract]]). The clone's runner rode that gadget until 2026-09-08; the standalone launcher (pogo_clone/device/launch_clone.py) mirrors Pokemod instead: kill injectors -> (optionally) restart game -> wait for libNianticLabsPlugin.so -> `frida.get_local_device().attach(pid)` + `create_script(runtime="v8")` + `init("early", params)` -> hold the session. Termux python frida 17.9.11 exposes `Device(id="local")`, which is frida-inject's injector.

**Current plaintext IS recoverable while Pokemod is live** (the on-disk agents/ files are encrypted; the injector decrypts before loading): `pogo_clone/device/scan_agent_text.py <pid> <out>` walks /proc/<pid>/mem read-only for a printable run containing agent markers. 2026-09-08 it yielded the main agent (2,278,147 B, banner `HAL Agent (81b909c7)`, a NEW custom `define(` bundle with mangled class names but intact method/string names) from the game, and the Go Plus agent (25,946 B; classes PokemodGoPlus3, BluetoothDeviceSimulator, PgpManager, EncounterManager, NativeJNI) from the :pgp process -- both filed under pogo_extract/system/analysis/pokemod/fresh_20260908/ with a README. Set MINRUN low (15000) for small agents. Anchor on strings, not class names, when reading the new bundle.

**Why:** "standalone, exactly like Pokemod" includes the launch path; reusing the gadget made the clone depend on ZygiskFrida and hid the fact that Pokemod and the clone can both be live in one process.

**Stock-Frida clash (2026-09-08 02:04, decisive):** python-frida's local device (= frida-inject) injects fine into a throwaway `sleep`, but into the GAME -- healthy, foregrounded, il2cpp up -- its agent connection drops within 2 s every time, because ZygiskFrida's stock frida-gadget is already in the process. Pokemod avoids this only because its injector is a renamed Frida ("floyd"). So on this phone the launcher's injection step attaches THROUGH the gadget (`--via gadget`, default) after mirroring every other HALService step; `--via inject` is kept for a device without ZygiskFrida, and `:pgp` (no gadget there) uses inject. Proven 02:09: `Injected into pid 15997 (runtime v8)`, `init("early")` accepted, pump on Zeppelin, rows cloned, Show IVs in Inventory painting cells.

**The REAL reason local injection into app processes failed (2026-09-08 20:17): SELinux, not only the gadget.** Termux's python-frida (`_frida.abi3.so`) injects its agent from memory and has NO `frida_selinux_patch_policy` symbol; under Enforcing the app domain refuses the agent and the connection drops in 0.3-0.4 s -- into the game AND into `:pgp` (which has no gadget). Pokemod's injector is frida-inject built `--with-selinux`, which calls that patch at start. Recipe that works on this phone, no downloads: the Termux devkit at `~/devkit/` (frida-core.h declares `frida_selinux_patch_policy`, `libfrida-core.a` 261 MB) + Termux clang -> `clang -Os -o frida_selinux_patch frida_selinux_patch.c -I. ./libfrida-core.a -ldl -lm -pthread -llog -Wl,--export-dynamic` (NO `-lresolv`, bionic has none) -> a 109 MB binary at `/data/local/tmp/frida_selinux_patch` that calls `frida_init(); frida_selinux_patch_policy();`. Run once per boot as root (policy stays Enforcing; frida adds its own rules, non-persistent); after it, python-frida local injection into `:pgp` loads and pings. `device/launch_clone.py` runs it before every `--via inject` step. Source (not in the repo): `~/devkit/frida_selinux_patch.c` (Termux) and `/data/local/tmp/frida_selinux_patch.c` on the phone.

**Two more rules learned 2026-09-08 20:20-20:32 (both agents live afterwards):** (1) ONE INJECTOR PROCESS PER TARGET, like Pokemod's one `pokemod-injector` per pid -- creating a second frida session (local device for :pgp) in the same python process that holds the gadget session dropped the gadget session immediately; `device/inject_one.py` is spawned/supervised per extra target. (2) frida-python delivers `console.log()` to `Script.set_log_handler(fn)` (default prints to stdout), NOT to the `message` handler -- a child whose stdout is /dev/null looks like a silent agent. The Go Plus bot's "Bot initialized successfully" appeared the moment the handler was installed.

**Go Plus bot live (2026-09-08 20:38):** with `--vpgp agent_vpgp/vpgp.js` the clone's transcription of Pokemod's vpgp agent paired and ran: Settings > Connected Devices and Services > Accessory Devices makes the game call `StartScanningWithFilter`; the bot injects one fake ScanResult per scan, so SELECT THE DEVICE WITHIN A FEW SECONDS (the entry ages out -- a first tap 20 s later found "No devices found"); then `Device.Connect` + `AndroidPeripheral.Connect` are short-circuited and the bot spins every stop and calls `CatchPokemon` on every nearby Pokemon (~1 encounter / 3 s). It consumes Poke Balls unattended -- eject it from Accessory Devices or kill the VPGP injector (`pgrep -f inject_one.py`) to stop.

**First live run of the clone launcher (2026-09-08 01:14):** Steps 1-2 mirrored theirs exactly (closed both pokemod-injector pids, force-stopped, `am start`, libNianticLabsPlugin.so seen at +1 s), but the inject at +1 s failed with "agent connection closed unexpectedly" and the game process vanished (tombstone_30 followed) -- their agent is built for that early stage, ours is not yet.
